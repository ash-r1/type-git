# Migrating to 0.4.0

0.4.0 strengthens the contract between typed inputs, Git's output, and return values. It contains source-breaking changes for callers using ambiguous repository flags, conflicting options, or alternate output formats. `raw()` remains available for arbitrary Git commands and returns unparsed stdout/stderr and the exit code.

## Repository types

Literal options still infer the precise repository type. A runtime boolean now returns `WorktreeRepo | BareRepo`. All repository objects expose a readonly `kind` discriminator:

```ts
const repo = await git.clone(url, destination, { bare: configuredBare });
if (repo.kind === 'worktree') {
  await repo.status();
} else {
  await repo.fetch();
}
```

`git.openRaw()` can be narrowed the same way, without assertions or asynchronous type checks. Node, Bun, and Deno now all export `TypeGit` from their runtime subpaths, with identical overloads.

## Output modes and return types

| Call | 0.4.0 result |
| --- | --- |
| `repo.lsTree('HEAD')` | `LsTreeEntry[]` with actual object metadata |
| `repo.lsTree('HEAD', { long: true })` | Entries with blob sizes where available |
| `repo.lsTree('HEAD', { nameOnly: true })` | `string[]` of paths |
| `repo.lsTree('HEAD', { objectOnly: true })` | `string[]` of object IDs |
| `repo.diff(undefined, { nameOnly: true })` | `string[]` of paths |
| `repo.diff(undefined, { nameStatus: true })` | `DiffResult` with actual status, rename source, and similarity |
| `config.getRaw(key)` | `string | undefined` |
| `config.getRaw(key, { all: true })` | `string[]`, including `[]` for a missing key |

Variable output-mode options return a union. Narrow the result or branch before calling when a precise type is needed. Filename-only results no longer invent blob metadata or mark every change as modified.

Status, tree, and structured diff queries use NUL-delimited output internally. Paths retain spaces, quotes, tabs, newlines, and Unicode. `status()` uses porcelain v2; `porcelain: 1` and `nullTerminated: false` are rejected. `showStash` now exposes `stash` when Git emits the header.

## Conflicting and unsupported options

Conflicts are rejected by TypeScript and by `GitArgumentError` before Git runs. This includes protocol selection, shallow-fetch modes, `fetch({ all, remote })`, `push({ all, refspec })`, force versus force-with-lease, checkout/switch creation modes, conflict-side selection, commit message sources, rebase/sequencer controls, LFS all-versus-filter modes, and mixed rev-parse queries. False flags remain valid when they do not activate a competing mode.

Control calls such as `rebase({ abort: true })` cannot also carry mutation options such as `upstream`. Pathspec files are a separate input mode:

```ts
await repo.add([], { pathspecFromFile: 'paths.txt' });
await repo.add(['src/index.ts']);
// Mixing the two input sources is rejected.
```

The typed API rejects these options; use `raw()` when that exact CLI behavior is needed:

| API | Options routed to `raw()` |
| --- | --- |
| `lsRemote` | `getUrl`, `symref` (use `remote.getUrl()` for configured remote URLs) |
| `status` | `verbose` |
| `log` | `source`, `decorate`, `decorateRefs`, `decorateRefsExclude`, `stat`, `shortstat`, `nameOnly`, `nameStatus` |
| `fetch` | `multiple` |
| `commit` | `dryRun`, `reeditMessage` |
| `diff` | `noIndex` |
| `cherryPick`, `revert` | `noVerify` (Git does not support this flag for these commands) |
| `config.list` | `nameOnly` |
| `lfs.pull` | `ref` (pull operates on the checked-out ref; use `lfs.fetch` for other refs) |
| `lfs.status` | `porcelain` |
| `lfs.lsFiles` | `debug`, `nameOnly` |

For example, use `repo.raw(['commit', '--dry-run'])` to inspect a prospective commit, rather than receiving metadata for an unrelated existing HEAD. `diff`'s `mergeBase` option is now a boolean flag; pass the comparison revision as `target`.

This does not model every Git version or repository state in the type system. Unsupported flags on an older installed Git, missing refs, authentication failures, and network failures remain runtime Git errors. Numeric counts and limits are checked at runtime because plain TypeScript `number` includes negative, fractional, and non-finite values.

## Lossless values and explicit errors

- Commit bodies now retain their whitespace and control characters. Apply `.trim()` explicitly if your application needs the former trimmed behavior. `log()` fixes the wire format and suppresses notes, signatures, decorations, patches, and color. `useMailmap` selects mailmap-aware fields.
- The exported `GIT_LOG_FORMAT` / `parseGitLog()` contract now uses eleven NUL-delimited fields with `git log -z`; update custom callers and fixtures using the previous SOH record separator.
- `parseRecords('\0')` now returns `['']`, preserving one empty value.
- Config reads preserve empty values, multiline values, and surrounding whitespace. Config enum values are checked and common boolean spellings are normalized. `config.list()` retains requested origin and scope metadata. Use `getRaw()` for values outside `ConfigSchema`.
- Missing config keys produce `undefined` (scalar) or `[]` (all values). Malformed config and cancelled operations throw, rather than masquerading as missing values.
- Merge conflicts return `{ success: false, conflicts }`. Other merge failures throw `GitError`; cancellation is always `Aborted`.
- `commit({ quiet: true })` returns real statistics from machine-readable output. Stash metadata is obtained in one formatted command.
- Malformed structured status/tree/log/LFS output throws `ParseError` rather than silently dropping records. Spawn failures are normalized to `GitError`.
- Already-cancelled repository operations do not spawn Git. Cancelled clone/init calls preserve destinations that existed before the operation.

## Git LFS

`lfs.status()` and `lfs.lsFiles()` always request JSON. Explicit `json: true` is accepted; `json: false` is rejected. Use a Git LFS version supporting JSON for both commands.

`LfsStatus.files[].status` is the actual Git LFS status code (for example `A` or `M`). `size` is optional; an unknown size is no longer fabricated as zero. `lfs.lsFiles()` returns full OIDs and exact byte sizes from JSON. Empty file lists are handled explicitly.

`lfs.fetch()` honors `dryRun`, `refetch`, and `json`, combines include/exclude arrays into comma-separated filters, and requests progress through `GIT_LFS_FORCE_PROGRESS` rather than an unsupported `--progress` flag. Git and LFS callbacks remain separate: `onProgress` and `onLfsProgress`.

## Validation and coverage

`pnpm typecheck` includes compile-time acceptance/rejection tests for public overloads and option combinations. The same repository scenario runs on Node, Bun, and Deno, in addition to real-Git regression tests and package installation tests. CI includes Node 20/22/24 on Linux/Windows and a Git 2.25 compatibility job. Version-dependent features such as config scope and status stash headers require the corresponding Git support.

Git's machine-output specifications: [status](https://git-scm.com/docs/git-status), [ls-tree](https://git-scm.com/docs/git-ls-tree), [diff](https://git-scm.com/docs/git-diff), and [config](https://git-scm.com/docs/git-config).
