# Migrating to 0.7.0

0.7.0 splits type-git into a lightweight main entry point and an opt-in strict entry point.
The grammar-checked `command()` moves from `Git`, `WorktreeRepo`, `BareRepo` and `TypeGit` to
`type-git/strict`. Everything else keeps its name and shape.

## Why

In 0.6.0 `command()` grew a catalogue of Git's option grammar for 428 command scopes. The
catalogue made `command()` far more accurate, but every user paid for it, including those that
never call `command()`:

| Measured on an application that only calls `repo.status()` | 0.6.0 | 0.7.0 |
| --- | --- | --- |
| Bundle (esbuild, minified) | about 1.6 MB | about 180 KB |
| Bundle, gzip | about 210 KB | about 45 KB |
| Type declarations loaded by the main entry | about 5 MB | about 350 KB |

The catalogue, the native parser probes that support it, and the literal grammar types now load
only when `type-git/strict` is imported.

## What stays in the main entry point

- `raw()` on clients and repositories.
- The high-level API (`status()`, `log()`, `commit()`, `branch.create()`, `lfs.*`, and so on),
  with the same option types and runtime option checks as 0.6.0.
- The checks against argument injection: operands that Git would read as options, NUL
  characters in arguments, and empty pathspecs are still rejected before Git runs. They are not
  opt-in.
- Parsers, adapters, `GitError` and `GitArgumentError`.

## Moving `command()` calls

Wrap the client or repository with `strict()`. The wrapper keeps every original member, so it
can replace the original object:

```ts
// 0.6.0
const repo = await git.open(path);
await repo.command('log', [['--oneline'], ['-n', '5']]);
await git.command('hash-object', [['--stdin']], { stdin: 'hello' });

// 0.7.0
import { strict } from 'type-git/strict';

const repo = strict(await git.open(path));
await repo.command('log', [['--oneline'], ['-n', '5']]);
await repo.status();
await strict(git).command('hash-object', [['--stdin']], { stdin: 'hello' });
```

`strict()` accepts objects created by type-git: `createGit()`, `createGitSync()`, `TypeGit`
from any runtime entry point, and the repositories returned by `open()`, `openBare()`,
`openRaw()`, `init()` and `clone()`. It throws `GitArgumentError` for other objects. Arguments,
options, results and errors of `command()` are unchanged.

If you do not need grammar checks, `raw()` runs any Git command without them:

```ts
await repo.raw(['log', '--oneline', '-n', '5']);
```

## Moved types

These types are exported from `type-git/strict` instead of `type-git`:

- `GitCommandArgument`, `GitCommandClient`, `GitCommandExecOpts`, `GitCommandName`

`type-git/strict` also exports `CheckedCommandArguments` and the wrapper types `Strict<T>`,
`StrictGit`, `StrictWorktreeRepo` and `StrictBareRepo`. Code that declared a variable with
`command()` as `Git` or `WorktreeRepo` can use these instead:

```ts
import type { StrictWorktreeRepo } from 'type-git/strict';

async function lastCommits(repo: StrictWorktreeRepo) {
  return await repo.command('log', [['--oneline'], ['-n', '5']]);
}
```

## `CliRunner.runCommand()`

`CliRunner` is still exported, with `run()`, `runOrThrow()` and the other execution methods, but
its grammar-checked `runCommand()` is removed. Create a client with `createGit()` or `TypeGit`
and call `strict(client).command()` instead.

## Custom adapters

The adapter contract is unchanged. `spawnBytes` is still needed only for
`strict(...).command(..., { stdout: 'bytes' })`.
