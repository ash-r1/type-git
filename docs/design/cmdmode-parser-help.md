# Ordered help and immediate mode conflicts

Git 2.55 `builtin/merge-base.c`, `builtin/patch-id.c` and `builtin/stripspace.c` use ordinary `parse_options` flags 0. Git 2.25 shares that parser for merge-base and stripspace, but patch-id still uses a manual zero-or-single-option argc dispatch; extra arguments produce a usage failure. Those older unsupported help/completion/repetition sequences retain their actual native usage errors and are not counted as successful commands. In the ordinary parsers, `OPT_CMDMODE` choices reject a different previously selected mode as soon as the conflicting option is reached. Repeating the same mode is permitted. These callbacks run before a later help flag; an earlier help exit bypasses later choices. This differs from final checks such as merge-base's all/independent restriction, which a help exit bypasses.

The command-local metadata adds internal `-h`, later `--help`, `--help-all` and sole-word completion handling. Existing mode groups implement the reached conflict; no shared runtime or type engine change is needed. First-word `--help` remains the documentation dispatcher path. Sole helpers preserve actual selected-Git output, including unsupported legacy full-helper errors; reached multiword helpers reject.

Known option shapes, NUL checks and the existing catalogue boundary remain active after help. Arbitrary unknown tail words remain a separate compatibility limitation. The finite probes terminate at help, completion or an earlier parsing error; merge analysis, patch hashing and whitespace payload semantics, configuration, abbreviations and complete platform/version grammar remain unproven. Every audit entry remains partial.
