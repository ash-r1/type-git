# Credential base command sole usage words

This change covers the base `credential` scope, leaving prefixed operation scopes unchanged. Git 2.55.0 calls `show_usage_if_asked` before exact operation arity. Git 2.25.1 checks `argc != 2` or sole `-h`, reads stdin for other one-word inputs, and uses usage for an unknown operation. Sole `--help-all` therefore preserves native usage outcomes without changing helper processing. Modern configuration is still read before usage; wrapper checks do not replace native config validation.

Command-local sole usage metadata, an exact one-word raw constraint, and first-word documentation dispatch prevent multiword help or later `--help` from bypassing operation validation. Tagged sole usage words share the operation value constraint, preserving safe operation/usage unions. Native capability availability stays delegated to the selected executable.

The finite 96-case baseline spans 12 argument/stdin forms on four Linux Git versions inside/outside a repository. It found 24 sole-usage rejections, including six native exit-zero rejections. Ordinary approve/reject controls use only fixed protocol/host text without username or password. HOME/XDG are isolated, system configuration is disabled, and an empty credential helper list is configured. No fill operation, actual credential, helper program or network request is used. Root entries, index, tracked content, HEAD, local config and isolated global config remain unchanged. Malformed credential input is tested separately. This does not establish helper/storage/network, complete protocol/version/platform behavior. All 430 scopes remain partial.
