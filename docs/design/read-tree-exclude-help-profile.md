# Selected read-tree exclude callbacks before help

Git 2.25's exclude callback accepts an arbitrary filename, rejects a second occurrence immediately, and checks the update requirement after option parsing. Newer source requires an earlier `-u` and `.gitignore` at each callback, while permitting repetitions. The source families therefore differ in three independent observations; a version number alone is not used to choose a family.

The runner observes the selected executable with three read-only, help-ended argument lists: exclude `.gitignore` without `-u`; `-u` with another exclude filename; and `-u` with two `.gitignore` occurrences. It selects a family only when all three outcomes match the source-audited signature. Outside-repository, localized, configuration or mixed observations preserve the original argv through native execution. Environment and abort signals are retained, and observations consume no caller stdin. Shape and NUL checks occur before observation.

This initial profile applies only to a reached exclude callback followed by an actual internal help exit. The legacy help walk skips the newer value/prerequisite checks and rejects a reached duplicate. Earlier help skips later callbacks; help-looking values, tagged operands and end markers do not create an exit. Generic literals may use the older alternative only when every resulting state reaches help; an explicitly modern context cannot borrow it, and an explicitly legacy context checks only this verified help walk. Failed flag-union arms are retained.

Without a later help exit, existing validation remains unchanged; old non-help callback/payload compatibility is still open. Internal help and sole completion are scoped to read-tree; first-word `--help` remains documentation dispatch. Known option catalogue, shape and NUL constraints remain active after help. The finite controls do not establish index/worktree updates, filesystem/concurrency behavior, all flag unions or complete platform/version grammar. All audits remain partial.
