# Selected read-tree exclude callbacks

Git 2.25's exclude callback accepts an arbitrary filename, rejects a second occurrence immediately, and checks the update requirement after option parsing. Newer source requires an earlier `-u` and `.gitignore` at each callback, while permitting repetitions. The source families therefore differ in three independent observations; a version number alone is not used to choose a family.

The runner observes the selected executable with three read-only, help-ended argument lists: exclude `.gitignore` without `-u`; `-u` with another exclude filename; and `-u` with two `.gitignore` occurrences. It selects a family only when all three outcomes match the source-audited signature. Outside-repository, localized, configuration or mixed observations preserve the original argv through native execution. Environment and abort signals are retained, and observations consume no caller stdin. Shape and NUL checks occur before observation.

The profile applies to a reached exclude callback before internal help or an end marker, including calls without help. The legacy walk accepts arbitrary filenames, rejects a reached duplicate immediately, and requires final `-u` unless parsing exits through help. Newer callbacks retain their earlier-`-u` and `.gitignore` requirements. Earlier help skips later callbacks; help-looking values, tagged operands and end markers do not create an exit. Generic literals choose a complete valid parser family; explicitly pinned contexts cannot borrow another family. Failed flag-union arms are retained.

A finite no-help dry-run corpus covers late/prior/missing `-u`, repetition, arbitrary and empty filenames, merge and reset modes on four Linux Git executables. Each native and API call checks unchanged index bytes, tracked file contents and `.git/HEAD` bytes in an isolated fixture. These observations do not establish actual index/worktree updates, all repository states, filesystem/concurrency behavior or complete platform/version grammar. Internal help and sole completion remain scoped to read-tree; first-word `--help` remains documentation dispatch. Known option catalogue, shape and NUL constraints remain active after help. All audits remain partial.
