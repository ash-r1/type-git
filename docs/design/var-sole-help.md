# var sole usage words

`builtin/var.c` in Git 2.55.0 calls `show_usage_if_asked` before its exact one-word arity and variable lookup. Git 2.25.1 instead reaches `usage` through the arity/unknown-variable branches. Sole `-h` and `--help-all` therefore produce usage on both versions, with native status and output stream differences retained.

The command-local metadata accepts canonical sole usage tuples and tagged usage operands. Canonical tuples have exact one-word checks and `singleWordExits`; tagged words pass the variable value constraint only under the existing exact one-word arity. Neither form permits a second argument. `--help` stays first-word documentation dispatch. Normal `-l` and supported variable queries remain unchanged, including native version availability and configuration behavior.

The baseline audit covers 96 cases: 12 argument forms on Git 2.25.1, 2.47.3, 2.55.0 and 2.56.0 inside and outside an isolated repository. It found 32 sole-usage pre-execution rejections, including eight native exit-zero cases. Successful fixed editor/pager queries and config listing act as ordinary controls; root entries, index, tracked content and HEAD remain unchanged. Unknown variables and multiword usage remain API validation errors. This finite audit does not establish exhaustive variable/version, configuration, filesystem, platform, or shell behavior. All 430 scope audits remain partial.
