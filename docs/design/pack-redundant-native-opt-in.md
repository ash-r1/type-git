# Selected-native pack-redundant acknowledgement

Git 2.25.1 has no acknowledgement prerequisite or `--i-still-use-this` option. The Git 2.41 release notes describe escalating the obsolete-command warning to an error; Git 2.55.0 calls `you_still_use_that` unless opted in. The pinned rule remains recorded, but public literal checking and the runner defer this version-dependent prerequisite to the selected executable, following the existing whatchanged policy. No version threshold or extra native probe is introduced.

Direct constraint evaluation without a native-owned context still enforces the pinned requirement. Other arity, flag-shape and callback rules remain active. The public runner preserves old successful output, modern deprecation diagnostics, and old-Git unknown opt-in failures without rewriting argv, stdin, env or signal.

The finite 96-case audit covers 12 argument forms on four Linux Git versions inside/outside repositories. Two actual SHA1 packs (a complete set and a blob subset) avoid the historical single-pack bug. The initial fixture used absolute pack filenames, which Git did not match against its relative packed_git names; that failed expected-success assertion and exploratory output remain recorded. Corrected relative filenames confirm five old-Git native successes rejected by the wrapper. Root entries, index, tracked content, HEAD, local config and every object-store file stay unchanged after fixture setup. No pack deletion or gc/repack operation is performed. Broader pack algorithms, deprecation backports, helper usage exits and platform behavior remain partial; all 430 scope audits remain partial.
