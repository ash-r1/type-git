# Shared dirstat callback grammar

The shared `diff_opt_dirstat` callback covers `--dirstat`, `-X`, `--dirstat-by-file` and valueless `--cumulative`. Bare optional arguments and cumulative's native preset remain supported. The optional-string spellings do not accept explicit public boolean values; cumulative remains a valueless flag. Source `PARSE_OPT_NONEG` is preserved. Common group overrides and stash-show's attached short option retain the callback. Cherry-pick/revert's first-pass `-X` remains a required strategy-option string; their retained diff dictionaries still carry the dirstat callback, without replacing that earlier parser.

`parse_dirstat_params` accepts whole empty text, otherwise comma-delimited exact `changes`, `lines`, `files`, `noncumulative`, and `cumulative`, or ASCII digit-first decimals with at most one dot. A trailing dot is accepted: the native fractional-digit test advances past the dot even when it finds the string terminator. Leading, interior and trailing empty fields in nonempty text fail. No whitespace trimming, case folding, sign, exponent, unit, or percent suffix is accepted. Native errors accumulate and cannot be cleared by later words; the reached callback dies with status 128.

Only lexical acceptance is modeled. Raw text is preserved; strtoul overflow, cutoff arithmetic, rendering and configuration-dependent stored state remain native-owned. The type parser preserves finite-union failure arms and the existing Dynamic/128-step conservative runtime escape, not complete symbolic or unbounded recognition. NUL, public argument shape, earlier callback errors and each frontend's help timing remain separate guards.

The baseline compares 6,204 native/API invocations across six Git versions, five help frontends and ordinary no-change diff controls. Short `-X` values attach without an equals sign. Twenty unused rejection assertions establish missing literal constraints. These finite controls do not complete a command audit.
