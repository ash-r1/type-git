# Diff output indicator callback

The three shared options `--output-indicator-new`, `--output-indicator-old`, and `--output-indicator-context` use `diff.c:diff_opt_char` in the inspected Git 2.25.1 and 2.55.0 sources. Their existing string shapes now share one registered byte-character callback. For nonempty JavaScript text, exactly one UTF-8 byte is accepted: a single ASCII code unit. Multi-character text, accented characters, astral characters and lone surrogates encode multiple bytes and are rejected when the callback is reached. Global argv checks still reject NUL, even in a skipped callback. Dynamic strings remain available and are checked at runtime. Invalid alternatives in a literal union must not disappear.

The callback inspects `arg[1]` without first requiring a nonempty argument. For an empty argv string, that reads past the terminator; its observed result varies with process layout. The registry explicitly leaves empty text native-owned. It preserves the empty argv spelling and makes no portable promise about native acceptance or rejection. Initial native/public observations and the failed initial empty-value parity fixture are retained in the audit ledger. Deterministic native matrices exercise nonempty values; unit and compiler controls preserve empty delegation.

All 27 shared diff scopes keep their existing callback/help phases. Five continuing parsers reach callbacks on both sides of short help, seven streaming parsers stop at their help exit, and fifteen initial parsers handle help before retained diff callbacks. Difftool's final tool-help selection remains before its retained parser. First-word documentation dispatch, ignored-tail shapes, separators and NUL checks are unchanged. Native tests compare status, streams and signal propagation on accepted/delegated inputs, specific callback diagnostics on rejected inputs, and repository state after every case. Missing builtins are explicitly skipped.

The change groups one callback and its three options across the affected command scopes in a single PR. Finite matrices and pinned source inspection do not establish every rendering mode, abbreviation, platform or native empty-string outcome. All command audits remain partial.

Standard verification exposed heap pressure at the unchanged 12,288 MiB limit; failed runs remain recorded. Constraint-state read-key traversal now recursively inspects the union of nested properties directly, avoiding a temporary mapped object. Declared/read key filtering uses intersection of the pinned catalogue's finite literal-key sets instead of distributive `Extract`. A separate compiler probe checked equivalence for every typed command name, representative unions and `never`. All original input cases, existing fixtures and runtime behavior are preserved. A focused comparison reduced instantiations from 3,342,225 to 3,081,085; this is a single-sample result, not a guarantee of whole-project memory use. Fresh standard whole-project and packed declaration checks remain required.
