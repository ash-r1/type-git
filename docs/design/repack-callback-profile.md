# Repack callback timing before help

Git 2.25.1 `builtin/repack.c` declares `--max-pack-size` as `OPT_STRING` and forwards the value to pack-objects after parsing. Git 2.55.0 declares `OPT_UNSIGNED`, which can reject a malformed value immediately. Both use ordinary parse-options internal help. Thus `repack --max-pack-size=invalid -h` reaches help on the older string path but fails at the earlier numeric callback on the modern path. Help before the option exits before either callback.

Scope-local metadata adds ordinary internal help, full help and sole-word completion exits, while keeping first `--help` documentation dispatch. A max-pack-size timing observation is needed only when the option precedes an actual internal help exit; end markers, help-looking operands, first documentation help and tuples without a help exit do not acquire an older timing alternative.

The runner observes the selected executable with `repack --max-pack-size=type-git-profile-invalid -h`. Usage status 0/129 without an error or fatal diagnostic selects deferred timing; the specific max-pack-size integer diagnostic at status129 selects immediate timing. Unknown, localized, configuration or outside-repository responses preserve the original argv through native execution. The observation inherits environment and abort signal, consumes no caller stdin and does not perform packing. Argument shape and NUL checks run before observation. This selects observed behavior rather than guessing a version threshold.

For the deferred help walk, only the marked max-pack-size option retains its raw value instead of invoking the modern numeric validator. Other callbacks and representation checks remain active. Tuples without a real internal help exit retain the existing validation path; this change does not establish the complete old packing grammar or payload behavior. Literal checking permits the older help alternative when timing is unknown, but an explicitly immediate context cannot borrow it. The repack walk retains failed flag-union arms instead of dropping them beside a successful help path; the deferred alternative still checks other callbacks and later argument shapes.

Integration tests compare native/API status, stdout and stderr for help and sole completion. A malformed max-pack-size before help is compared exactly when selected native Git reaches usage; when native Git rejects the numeric callback, the test separately checks that native error and the API exception. Reached multiword helpers likewise check native unknown-option errors and API rule IDs separately. Mock runner tests cover environment, stdin, abort, unknown-response fallback and malformed representation boundaries. The finite external corpora cover four Linux Git binaries inside and outside a repository; native nonzero outcomes are retained as failures.

All 430 command audits remain partial. Other option availability, callbacks, arbitrary argv/configuration, packing payload behavior and platform coverage are separate obligations. No complete compatibility or static numeric grammar across every native implementation is claimed.
